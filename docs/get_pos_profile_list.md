# FadlPos: список POS Profile и статус смены (`get_pos_profile_list`)

Документация по методу **`fadl_pos.api.pos_profile_list.get_pos_profile_list`**: какие профили кассы видит текущий пользователь и есть ли открытая смена по каждому профилю.

---

## Зачем это нужно

- Клиент POS после входа по сессии запрашивает **не все** профили компании, а только те, где пользователь указан в таблице **Applicable for Users** (в ERPNext это дочерняя таблица **`POS Profile User`**).
- Для каждого такого профиля возвращается блок **`shift`**: открыта ли смена по документу **POS Opening Entry** (логика согласована с проверкой открытой смены в нативном POS).

Зависимость от данных **ERPNext**: должны существовать документы **`Company`**, **`POS Profile`**, **`POS Opening Entry`** и связанные записи.

---

## Эндпоинт и вызов

| Способ | Значение |
|--------|----------|
| Метод | **`GET`** или **`POST`** (стандарт Frappe для `@frappe.whitelist`) |
| Путь v1 | **`/api/method/fadl_pos.api.pos_profile_list.get_pos_profile_list`** |
| Путь v2 | **`/api/v2/method/fadl_pos.api.pos_profile_list.get_pos_profile_list`** |

**Аутентификация:** обязательна. **`allow_guest=False`** — без сессии (или как **Guest**) метод недоступен, ожидайте ошибку аутентификации («Log in to continue»).

Передайте cookie **`sid`** (обычная сессия после логина) или другой поддерживаемый способ авторизации Frappe.

---

## Параметры запроса

| Имя | Тип | Обязательность | Описание |
|-----|-----|----------------|----------|
| **`company`** | строка | Нет | Компания для фильтра профилей. Если не передана или после обрезки пробелов пусто — берётся **дефолтная компания пользователя** (`User Default` для ключа **Company**). Если и её нет — ошибка с текстом вроде «Please set a default Company or pass company in the request». |

После выбора значения выполняется проверка: документ **`Company`** с таким именем должен существовать в базе. Иначе — **`DoesNotExistError`** («Company … not found»).

---

## Ответ при успехе

Тело ответа — объект верхнего уровня (в обёртке v1/v2 согласно версии API):

```json
{
  "user": "user@example.com",
  "company": "Demo Company",
  "profiles": [
    {
      "name": "Shop POS",
      "company": "Demo Company",
      "disabled": 0,
      "warehouse": "Stores - DC",
      "letter_head": null,
      "shift": {
        "is_open": true,
        "opening_entry": "POS-OE-00001",
        "cashier": "user@example.com",
        "period_start_date": "2026-04-27",
        "status": "Open"
      }
    }
  ]
}
```

### Поля

- **`user`** — имя пользователя из текущей сессии (не из параметров клиента).
- **`company`** — фактически использованная компания (из параметра или дефолта).
- **`profiles`** — массив профилей, удовлетворяющих условиям ниже.

Каждый элемент **`profiles`** содержит поля из **`POS Profile`** (минимум **`name`**, **`company`**, **`disabled`**, **`warehouse`**, **`letter_head`** — как в текущей выборке сервера) и вложенный объект **`shift`**.

### Объект **`shift`**

| Ключ | Описание |
|------|----------|
| **`is_open`** | **`true`**, если есть ровно один подходящий субмитнутый **POS Opening Entry** для этого профиля: **`docstatus = 1`**, **`status = Open`**, **`pos_closing_entry`** пустой. Иначе **`false`**. |
| **`opening_entry`** | Имя документа открытия смены или **`null`**. |
| **`cashier`** | Поле **`user`** из этого opening entry или **`null`**. |
| **`period_start_date`** | Дата начала периода или **`null`**. |
| **`status`** | Статус документа или **`null`**. |

Если смена не открыта, сервер возвращает **`is_open: false`** и **`null`** в перечисленных полях (кроме **`is_open`**).

---

## Кто попадает в **`profiles`**

Одновременно выполняются условия:

1. Профиль принадлежит выбранной **`company`**.
2. В дочерней таблице **`POS Profile User`** есть строка с **`user`** = текущий пользователь сессии (**явное** совпадение; пустой список «для всех» не подставляется).
3. Профиль не отключён: **`disabled`** не задан или равен **`0`**.

Профили той же компании **без** строки для текущего пользователя в **Applicable for Users** в ответ **не входят**.

---

## Типичные ошибки

| Ситуация | Ожидаемое поведение |
|----------|---------------------|
| Нет сессии / Guest | **`AuthenticationError`** |
| Нет компании ни в параметре, ни в дефолтах пользователя | **`ValidationError`** |
| Неверное или отсутствующее имя **Company** | **`DoesNotExistError`** |

Точные тексты сообщений могут локализоваться через **`_()`**.
